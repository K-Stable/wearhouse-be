# 무신사 사례 참고 메모

## 목적

- 무신사 기술 블로그 사례에서 우리 프로젝트에 바로 적용 가능한 원칙을 추려 의사결정 근거로 사용한다.

## 참고 글

- 나야, 주문: 주문시스템의 도전과 성장 이야기
- 무진장 힘들었지만, 무진장 성장한 개발 이야기
- 재고 서비스의 진화와 혁신: 지속적인 개선을 통한 안정성과 확장성 강화

## 적용 결정

| 항목 | 적용 여부 | 우리 프로젝트 적용 방식 |
|---|---|---|
| CQRS | 적용 | 주문/결제 커맨드 경로와 조회 경로 분리 |
| 이벤트 기반 아키텍처(EDA) | 적용 | Kafka + Outbox/Inbox + DLQ |
| Saga 보상 트랜잭션 | 적용 | 주문-재고-결제 실패 시 자동 보상 |
| 재고 다층 방어 | 적용 | Redis 원자연산 + 분산락 + DB version |
| 캐시 워밍/스탬피드 대응 | 적용 | 핫 SKU/핫 상품 선적재 파이프라인 |
| ERP/외부 연동 대사 | 적용 | 실시간 + 배치 대사 병행 |
| AIOps 기반 이상 감지 | 단계 적용 | 1차 룰 기반, 2차 동적 임계치 |
| 기능 플래그/킬스위치 | 적용 | 고위험 기능 점진 배포 + 즉시 차단 |

## 벤치마크 참고 수치(원문 사례)

| 항목 | 사례 수치 | 우리 적용 포인트 |
|---|---|---|
| 피크 트래픽 대응 | 분당 약 400만 요청(사례) | 조회/커맨드 경로 분리와 캐시 전략 선행 |
| 주문 처리량 대응 | 분당 약 1만 주문(사례) | 주문 Saga + 이벤트 처리량 산정 기준 수립 |
| 재고 API 성능 개선 | 배치 5,000 SKU p95 10s -> 900ms(사례) | 배치 API/캐시/병렬화 목표치 설정 |
| 품절취소율 개선 | 약 3.4% -> 0.54%(사례) | 재고 다층 방어 + 대사 자동화 KPI화 |

|---|---|---|
